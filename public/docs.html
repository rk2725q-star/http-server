1. What is a Web Server?

A web server is software (and underlying hardware) that listens for incoming network connections from clients (such as web browsers), processes their requests according to the Hypertext Transfer Protocol (HTTP), and transmits back responses containing HTML pages, media files, or JSON API data.

2. Client-Server Architecture

In the client-server paradigm, communication is asymmetric:

  • Client (Active Initiator): Establishes a TCP connection to the server's IP address and listening port, transmits an HTTP request, and waits for a response.
  • Server (Passive Listener): Binds to a local network interface and port, continuously listens for incoming connections, and processes multiple client requests concurrently.

3. TCP & Sockets Explained

The Transmission Control Protocol (TCP) operates at the Transport Layer (Layer 4) of the OSI model. TCP provides reliable, ordered, error-checked delivery of a stream of octets (bytes) between applications running on hosts communicating via an IP network.

The 3-Way Handshake

Client                          Server
  │                               │
  │─── SYN (Seq = X) ────────────▶│  1. Client initiates connection
  │                               │
  │◀── SYN-ACK (Seq=Y, Ack=X+1) ──│  2. Server acknowledges and responds
  │                               │
  │─── ACK (Seq = X+1, Ack=Y+1) ─▶│  3. Connection ESTABLISHED!
  │                               │

What is a Socket?

A socket is an endpoint of a two-way communication link between two programs running on the network. A socket is uniquely identified by the combination of an IP Address and a Port Number.

Socket Lifecycle in NetServe

  1. socket.socket(AF_INET, SOCK_STREAM): Creates an IPv4 TCP stream socket.
  2. setsockopt(SOL_SOCKET, SO_REUSEADDR, 1): Enables immediate port reuse upon restart.
  3. bind(('127.0.0.1', 8080)): Associates the socket with host IP 127.0.0.1 and port 8080.
  4. listen(100): Puts the socket in passive listening mode with a connection backlog queue of 100.
  5. accept(): Blocks until a new client connects, returning a new client socket and client address tuple (IP, Port).
  6. recv(4096): Reads incoming byte chunks from the TCP stream.
  7. sendall(data): Transmits the HTTP response bytes back across the TCP stream.
  8. close(): Tears down the connection.

4. HTTP/1.1 Request Structure

An HTTP/1.1 request is an ASCII text stream separated by CRLF (\r\n) line endings: 

┌────────────────────────────────────────────────────────┐
│ Request Line:  GET /api/status HTTP/1.1\r\n             │
├────────────────────────────────────────────────────────┤
│ Headers:       Host: 127.0.0.1:8080\r\n                 │
│                User-Agent: Mozilla/5.0...\r\n          │
│                Accept: application/json\r\n            │
│                Connection: keep-alive\r\n              │
├────────────────────────────────────────────────────────┤
│ Empty Line:    \r\n                                    │
├────────────────────────────────────────────────────────┤
│ Optional Body: [Payload data if POST/PUT]\r\n          │
└────────────────────────────────────────────────────────┘

6. HTTP Status Codes Quick Reference

2xx Success

200 OK: Standard response for successful HTTP requests.

201 Created: Request fulfilled and new resource created.

204 No Content: Server successfully processed request, returning no body.

4xx Client Errors

400 Bad Request: Malformed request syntax or invalid characters.

404 Not Found: Requested resource does not exist.

405 Method Not Allowed: HTTP method (e.g. DELETE) is disabled.

413 Payload Too Large: Request size exceeds 1MB limit.

431 Headers Too Large: Header fields exceed 8KB.

5xx Server Errors

500 Internal Server Error: Server encountered an unhandled exception.

501 Not Implemented: Server lacks ability to fulfill the request.

503 Service Unavailable: Server temporarily overloaded.

7. Concurrency: Multi-Threading in NetServe

In a single-threaded server, if a client experiences network latency or takes 5 seconds to download an asset, all other connecting clients are blocked. NetServe employs Python's concurrent.futures.ThreadPoolExecutor. When accept() yields a new client connection, the socket handle is submitted to an idle worker thread in the pool.

8. Step-by-Step Request Lifecycle in NetServe

  1. TCP Connection Established: OS finishes TCP 3-way handshake on port 8080.
  2. Accept Loop: NetServeServer accepts the socket and submits it to ThreadPoolExecutor.
  3. Buffer Ingestion: ClientHandler reads socket stream into a buffer until \r\n\r\n is identified.
  4. HTTP Parsing: HTTPRequestParser validates the request line, extracts method, URI, headers, and query parameters.
  5. Routing: Router checks registered routes (e.g., /api/status) or delegates to resolve_file_path for static files.
  6. Response Construction: ResponseBuilder serializes the status line, RFC-compliant Date header, Server header, MIME Content-Type, Content-Length, and body.
  7. Transmission: Serialized bytes are sent over the socket via sendall().
  8. Telemetry Logging: Latency and status are logged to server.log and recorded in NetworkMonitor for the live dashboard.
